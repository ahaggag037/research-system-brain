# OPTIONAL STUCKNESS TOOLKIT
## Do not read during normal discovery unless you become conceptually stuck

This file intentionally stays outside the default discovery path to reduce anchoring.

If discovery becomes repetitive, use these prompts:

- What assumption are all current architectures sharing?
- What if timing matters more than magnitude?
- What if the visible bottleneck is a dependency bottleneck?
- What if the correct action is to reduce work rather than allocate more resources?
- What if one resource should be treated as a budget rather than a target?
- What if the system should predict a bad state rather than react after it?
- What if competing controllers should be modeled as a coordination problem?
- What if the problem resembles queueing, congestion, caching, control, fault tolerance, or another non-Android domain?
- What information would most change the architecture if learned?
- What “dangerous” idea contains a useful submechanism whose hazard comes from only one dimension?
- What can be tested in shadow mode with zero intervention?
- Which two mediocre ideas could become strong when composed?

Use these only to restart divergent thinking, not as a required idea list.
